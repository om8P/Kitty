# S12: Test deploy on Northflank

Answers arch Q10: do Northflank Sandbox's limits fit the app, its database and its builds? This file leaves out the public URL and team name, because the repo is public.

**Status:** the local part is done. The Northflank part is waiting for the owner (see "Owner guide").

## What was added

- `Dockerfile`: a multi-stage `node:22-alpine` build that runs Next's standalone server as the non-root `node` user on port 3000. No secrets are used at build time.
- `.dockerignore`: keeps `.env*` (except `.env.example`), `.git`, `.claude`, `.spike-logs`, docs and `node_modules` out of the build context.
- `next.config.ts`: `output: "standalone"`. `npm start` still works locally. Next prints a warning that `next start` doesn't support standalone, but it serves normally.
- `/api/health` now returns `{ status, db, uptimeSeconds }` and logs `health ok db=<status>` on every call. `db` is `ok`, `error` or `unconfigured`, and it never contains error text. A database failure still returns 200, so the host never restarts the app over the database. A reset `uptimeSeconds` shows the process restarted or slept.
- `src/db/ping.ts`: `pingDatabase()` runs `SELECT 1` through `pg` 8.23.1, with 2-second connect and query timeouts.

## Owner guide

You do these steps in your own Northflank login. Agents never enter credentials or copy the database connection string. **If any screen asks for a card or payment method, stop, add nothing, and tell the agent.** S12 then becomes `blocked` and we move to the arch Q10 fallback.

1. **Project:** create a project in the Sandbox (free) plan, in any region.
2. **Repo access:** connect GitHub through Northflank's GitHub app and give it access to this repository only.
3. **Service:** create a combined service (build and deploy):
   - Repository: this repo. Branch: `step/S12-northflank-deploy`.
   - Build type: Dockerfile, at `/Dockerfile` with context `/`.
   - Compute: the smallest Sandbox plan.
   - Port: `3000`, HTTP, public.
4. **Database:** create a PostgreSQL add-on on the free tier. Link its connection string to the service as `DATABASE_URL`. In Northflank this is a secret group linked to the add-on, or the add-on's own "link to services" option **[verify UI name]**.
5. **Cron job:** create a cron job:
   - Schedule: `*/5 * * * *`.
   - Image: external image `curlimages/curl:latest`.
   - Command override: `curl -fsS https://<service public URL>/api/health`.
6. **Tell the agent:** say when it's deployed and give the public URL in chat (it won't be committed). Then share the build log duration, the service's metrics, and the plan's resource limits as text or screenshots, or open them in the built-in browser pane for the agent to read.
