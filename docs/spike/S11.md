# S11: Channel3 sample and terms

Run on 2026-11-10 with `scripts/spike/channel3-sample.ts` against `POST https://api.trychannel3.com/v1/search`. Raw responses stay in the gitignored `.spike-logs/`. This file records field names and types only, with no product data.

**Searches used: 2 of the 5 allowed.** S27 starts its counter from 2 for November 2026.

## Results

- **Fields known.** Both searches returned the same shape, which matches Channel3's OpenAPI schema. One docs example is wrong: price is `offers[].price.price`, not `amount`.
- **Free credits are monthly.** Channel3 gives 1,000 free credits every month. A search costs 1 credit, and product detail (`GET /v1/products/{id}`) is free. ([Pricing](https://channel3.ai/docs/pricing), read 2026-11-10.)
- **No surprise charges.** Once the free credits are used up, the API returns `402` with "Add a payment method to continue." It doesn't bill without a card. ([Search API reference](https://channel3.ai/docs/api-reference/v1/search), 402 response.)
- **Terms are still open for Kitty's use.** They allow building Channel3 into an app and showing its output to end users, but they say nothing about sandbox checkouts. Channel3's own caching guide recommends keeping product details only for minutes to hours. The question below asks about both.

## Request

| Item | Value |
|---|---|
| Endpoint | `POST https://api.trychannel3.com/v1/search` |
| Auth | `x-api-key` header (Bearer is also accepted) |
| Body used | `{ query, limit: 5, config: { country: "US", currency: "USD" } }` |
| Limit | Default 20, max 30. Every call costs 1 credit, whatever the limit |
| Default filters | `conditions: ["new"]`, `availability: ["InStock"]` |
| Optional header | `x-user-id`, which attributes clicks for commissions. Kitty doesn't send it |
| Paging | `page_token` from `next_page_token` |

## What S26 and S27 need to know

- **Price conversion.** Use `Math.round(price * 100)` for integer cents. Drop an offer whose currency isn't `USD`.
- **Choosing an offer.** A product can have several offers, so S27 needs a rule. A simple one: the cheapest offer that is `InStock`, `new` or null condition, and `USD`, whose `domain` maps to a Kitty store. If none qualifies, drop the product.
- **Store mapping.** Map on `offers[].domain`, with `category.slug` as a fallback hint.
- **Monthly counter.** Count searches per calendar month, not once. The 900 cutoff still applies **[verify]**: whether Channel3 resets on the calendar month or on the signup anniversary isn't documented. Check the dashboard.
- **Free product detail.** `GET /v1/products/{id}` costs no credits. `getProduct` could refresh a stored product at purchase time instead of keeping full details for 24 hours, and that would follow Channel3's caching guide. This depends on Channel3's answer.
- **Untrusted text.** `title`, `description`, `key_features`, `alt_text` and attribute values are all untrusted product text (arch 7.4).
- **Never store or show** `offers[].url`. Kitty shows no retailer links, so no commission disclosure is needed.

## Terms notes

From the [Publisher Terms](https://trychannel3.com/terms/publishers), effective 2026-11-02, read 2026-11-10. These are paraphrases, not legal advice.

- **Sec. 4 and 5:** Channel3 may be built into an app, and its output may be shown to that app's end users. End users may never get the API key. Kitty keeps the key on the server.
- **Sec. 7:** No caching or storing a significant portion of the catalog or output, no building a competing catalog, and no training models on the output. Kitty's per-search, short-retention design fits this. The 24-hour window is the open part.
- **Sec. 7:** No publishing benchmark or evaluation results about Channel3 without written consent. Kitty's repo should hold no quality comparisons of Channel3 results.
- **Sec. 2:** Publishers must be 18 or older, and the Services are "not directed to children". Kitty's demo includes a teen member who sees Channel3 products through Kitty. The question asks about this.
- **Sec. 8:** Queries must carry no names, emails or other identifiers, because Channel3 may show queries to merchants. S27 sends only the search text, and the agent's task text must never go to Channel3 unchanged.
- **Sec. 9:** Output may be wrong, and we must verify it before checkout. A sandbox checkout with no real order keeps that risk low.
- The [caching guide](https://channel3.ai/docs/guides/caching) says IDs may be kept indefinitely. Titles, descriptions and images may be kept for a short time (minutes to hours). Prices, availability and offers should be refreshed before they're shown.
