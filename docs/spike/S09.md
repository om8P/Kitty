# S09: AG Grid and Drizzle row locks

Run on 2026-11-10 against local Postgres 17 and a throwaway Next.js 16.4.6 page. The throwaway code has been removed.

**Versions tested:** `ag-grid-community` and `ag-grid-react` 36.3.0 (MIT), `drizzle-orm` 0.45.4, `pg` 8.23.1, `@types/pg` 8.23.1. S19 and S34 should start from these.

## Results

- **Row lock approach confirmed.** Drizzle takes the arch 7.1 lock with no raw SQL, and a second transaction waits for it.
- **Q9 answered: yes.** AG Grid Community covers everything the ledger needs. S34 needs three adjustments, listed below.

## Drizzle row locks

| Test | Result |
|---|---|
| Second transaction waits | **Pass.** `pg_stat_activity` showed `wait_event_type: Lock`, `wait_event: transactionid`, one blocking process. After the first transaction committed, the second read $10, not $40 |
| $40 pool, two concurrent $30 reservations, 25 rounds | **Pass.** Exactly one succeeded every round, leaving $10 available and $30 reserved |
| Control: same race with no lock | Both reservations passed, so the lock is what prevents overspending |
| Generated SQL | `select ... from "s09_spike_pools" where "s09_spike_pools"."id" = $1 for update` |

For S20:

```ts
await db.transaction(async (tx) => {
  const [pool] = await tx
    .select()
    .from(pools)
    .where(eq(pools.id, poolId))
    .for("update");
  // re-run the rules, then update and append ledger entries
}, { isolationLevel: "read committed" });
```

- Import `drizzle` from `drizzle-orm/node-postgres` and build it on a `pg.Pool`.
- The `tx` handle is a `NodePgTransaction`, which extends `PgTransaction` from `drizzle-orm/pg-core`. S20's port should wrap it in `src/db` so `src/domain` never imports it.

### What S34 needs to do

1. **Make Approve and Deny reachable by keyboard.** By default Tab moves between cells and skips the buttons, and Enter on the cell does nothing. Adding this to the column fixed it: Tab and Shift+Tab reach both buttons, and Enter activates them.
   ```ts
   suppressKeyboardEvent: ({ event }) => event.key === "Tab"
   ```
   Once a decision removes the buttons, focus falls back to the page body. S34 should move it somewhere sensible, for example with `api.setFocusedCell`.
2. **Handle phone width.** At 390px the page doesn't overflow, but the grid is 900px wide and scrolls inside its 343px area, leaving Decision off-screen. Pinning Decision to the right brought the buttons into view, at the cost of squeezing the other columns. S34 should pin it and hide lower-value columns at narrow widths.
3. **Size for the rules in `rules.md`.** Default rows are 42px, and unstyled buttons were 21px tall, too small for touch. The focused cell gets a thin blue border, so check it's visible enough or strengthen it. Column resize handles still show as grey bars in the header when `headerColumnBorder` is false.

### CSV export notes for E2

`getDataAsCsv` exports formatted values (`$5.00 USD`) and includes the empty Decision column. Pass `columnKeys` to leave it out.
